# Backend test scenario ledger

This ledger lists every backend test scenario, the decisions that shape them and the accepted mapping from the removed legacy tests. Requirements are in the [testing specification](backend-testing-spec.md). Earlier dated run evidence is in Git history; this file describes the current state.

## Format

Scenarios use stable IDs `BE-<AREA>-NNN`, never reused. Each test names its scenario in a `// BE-...` comment above the test method; the catalog below is generated from those comments. Integration tests use real HTTP, ASP.NET Identity and SQL Server in a disposable container; unit tests cover pure rules. A case count of `MemberData` means the cases come from a data method.

## Current gate

`vp run check` builds once, compares the generated OpenAPI and frontend client, runs frontend lint, types and unit tests, then the native MTP unit and SQL integration suites. It rejects missing, empty, failed or skipped backend reports. On 2026-10-09 it runs 643 cases: 220 frontend, 47 unit and 376 SQL integration, with no skips. Hosted Workspace CI runs the same command.

## Settled decisions

- Production runs v2.5.1. BE-UPGRADE-001 migrates a synthetic v2.5.1 database with Polish Unicode content to the current schema.
- A supervisor's first decision is final. A repeat or reversal returns 403 without state or email changes; the review link stays readable (BE-SUPERVISOR-001).
- Other users' drafts are hidden and uneditable, including for Administrator and Administrator + CruiseManager. Only manager or deputy assignment grants access; concealed records return 404. An assigned single-role Shipowner may write forms; an unrelated one may not.
- Cruise-number allocation, aggregate scoring overflow and remaining role combinations keep their current behavior, deferred to #438, #439 and #440.
- Drafts may contain partially filled rows, but every row key must be present. Omitting a key for a required SQL column returns 400 with a field error, even in a draft (BE-FORM-FIELD-001/002). The frontend always sends every key, using empty strings for unfilled values. Confirmed by the maintainer on 2026-10-09.
- Validation errors are keyed by camelCase JSON path, e.g. `form.permissions[0]`, with Polish messages. Failures without field errors carry a Polish `detail` (BE-INFRA-007); this came from staging #424.
- Input-rejection theories run as drafts only. The final-submission copies repeated the same rule and were removed on 2026-10-09 (58 cases). Final-submission rejection stays covered by BE-FORM-VALIDATION-001, BE-FILE-003 and the workflow tests.
- No CI time budget is enforced. A hosted Workspace CI job under five minutes is a goal. The job timeout is 10 minutes, as a hang guard.
